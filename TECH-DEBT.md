# Technical Debt

Honest audit of the codebase as of 2026-07-06. Generated by a thermo-nuclear code quality review using three parallel review agents (large files, supporting modules, tests/config).

Verdict up front: **the project is not following best practices in several concrete, load-bearing ways.** It works, it ships a build, and the AI runtime is genuinely wired off — but it carries ~1,400 lines of duplicated boilerplate, ~600 lines of commented-out "preserved" code, a real product bug from copy-paste drift, a manifest/auth mismatch that makes OAuth dead as shipped, and a test strategy that uses the wrong runner for ~60% of its suite. The Phase-1 verification criteria in `AGENTS.md` are effectively unverified by automation: the three largest files (`options.tsx`, `background.ts`, popup `App.tsx`) have **zero tests**.

This document is the debt register. Severities: **P0** (ship blocker / real bug), **P1** (real cost, fix soon), **P2** (smell, fix when touching the area).

---

## P0 — Ship blockers and real bugs

### P0-1. OAuth is dead as shipped: `manifest.json` has no `identity` permission

`manifest.json:26` declares only `["alarms", "storage"]`. `src/background.ts:749` calls `chrome.identity.getAuthToken({ interactive: true }, ...)`. Without `identity` + an `oauth2` block, `chrome.identity` is `undefined`, the guard at `background.ts:744` always fires, and every "Connect YouTube" click resolves to `{ error: "Chrome identity API is unavailable." }`.

`vite.config.ts:9-21` only injects `identity` + `oauth2` when `GOOGLE_CLIENT_ID` is set at build time. The README says Phase 1 builds without it. So the entire YouTube account feature — playlists, subscriptions, channels, the options-page "Connect YouTube" button — is a dead button in any build that ships without the env var. No test verifies this graceful degradation. `progress.md` marks T102/T103/T102A as "Done" — they were verified by testing message *shapes*, not the actual `chrome.identity` call.

**Fix:** either ship the `identity` permission + `oauth2` block (requires the client ID) or gate the entire "Connect YouTube" UI behind a build flag so the dead button doesn't ship. Document which build is the release build.

### P0-2. `mapErrorResult` 403 handling drifted — real product bug

`src/youtube/api.ts:132-139` treats HTTP 403 as potentially `channel_required` (checks `isChannelMissingError`). The three sibling modules don't:
- `src/youtube/subscriptions-api.ts:147` — 403 → `unavailable`
- `src/youtube/channel-api.ts:120` — 403 → `unavailable`
- `src/youtube/preview-api.ts:121` — 403 → `unavailable`

The YouTube Data API returns 403 for several channel-related conditions. Users without a YouTube channel get "Retry soon" instead of "Create a YouTube channel" on subscriptions/channel/preview fetches. The type system allowed the drift because each module defines its own inline failure-status union. This is the bug the copy-paste was always going to produce.

**Fix:** one shared `mapYouTubeApiError(statusCode, payload)` with `channel_required` handling everywhere. Delete the four inline copies.

### P0-3. `@ai-sdk/openai` and `ai` are in production `dependencies` for a "non-AI release"

`package.json:21,27`:
```json
"@ai-sdk/openai": "^3.0.63",
"ai": "^6.0.176",
```
`progress.md:78` brags about "a built-output scan confirming no OpenAI host permission or AI sticker strings." The scan checked the bundle, not `package.json` or `node_modules`. Reviewers will ask why an AI SDK ships in a release that explicitly claims AI is disabled. `src/ai/stickers.ts:1` still `import`s from these packages — the modules are live source, kept green by `tests/ai-*.spec.ts` (which are `describe.skip`).

**Fix:** move to `optionalDependencies` or delete and re-add from git when AI work reopens. If you keep them, the "non-AI release" claim is incoherent.

### P0-4. No schema versioning or migration on any of 8 stored state shapes

`FocusSettings`, `YouTubePlaylistState`, `YouTubeSubscriptionState`, `YouTubePlaylistPreviewState`, `YouTubeChannelPreviewState`, `YouTubeAuthState`, `AiSettings`, `AiStickerCacheState` — none carry a `version` field. Each `normalizeX` silently merges by reading known keys and falling back to defaults for missing ones. The first post-release schema change (rename a field, change a type, split a field) silently loses every user's stored data with no migration path and no signal.

**Fix:** add `version: 1` to each shape and a `migrate(fromVersion, data)` hook in each storage module. Cheap now, expensive after shipping.

### P0-5. `subscribeToFocusSettings` fires up to 17 authenticated YouTube API calls on every settings toggle

`src/background.ts:121-125`:
```ts
void subscribeToFocusSettings(() => {
  void syncSelectedPlaylistPreviews();
  void syncSelectedChannelPreviews();
  void syncTemporaryDisableBadge();
});
```
`syncSelectedPlaylistPreviews` loops up to 12 imported playlists (1 HTTP each). `syncSelectedChannelPreviews` loops up to 5 channels (1 HTTP each). **Every** settings change — including flipping `focusModeEnabled` true↔false — fires both. Toggling focus mode off triggers up to 17 authenticated YouTube API calls that do nothing useful because the playlist/channel selections didn't change. Burns quota, burns battery, races the UI. The `void` swallows rejections silently.

**Fix:** diff `importedPlaylists`/`selectedChannels` against the previous settings before re-fetching. Debounce. Surface errors.

### P0-6. `package.json` still named `react-chrome-extension-template`

`package.json:2`:
```json
"name": "react-chrome-extension-template",
```
`manifest.json:3` says "YouTube Focus Extension." The package was never renamed. `scripts/setup.js` exists to do this interactively but was never run. Shows up in `npm pack`, lockfiles, and any tooling that reads package metadata. Embarrassing for a Chrome Web Store release.

**Fix:** rename to `youtube-focus-extension`. One line.

### P0-7. The three largest, most important files have zero tests

| File | Lines | Tests |
|---|---|---|
| `src/options.tsx` | 1460 | 0 |
| `src/background.ts` | 764 | 0 |
| `src/App.tsx` (popup) | 234 | 0 |
| `content-script/src/App.tsx` | 1049 | 0 |

Every "verification" entry in `progress.md` says "Playwright passed N tests" — but those tests cover extracted pure functions, not the React UI or the service worker. The AGENTS.md Phase-1 completion criteria ("popup toggle updates the content script without a reload," "options page persists playlist settings," "default/off state does not break normal YouTube browsing") are effectively unverified by automation. T12 is still "Blocked" because "live Chrome manual verification was not completed" — and there's no automation to fill the gap.

**Fix:** at minimum, add jsdom-level render tests for the popup and options, and a `chrome.storage` fake-based test for the background message router. The pure-function extraction pattern is good; it's not a substitute for testing the things that compose the functions.

## P1 — Real cost, fix soon

### P1-1. ~1,400 lines of duplicated boilerplate across 4 parallel families

Four families (`youtube/`, `subscriptions-*`, `channel-*`/`channel-preview-*`, `preview-*`) each follow `schema + storage + api + status-copy`. ~90% of each `*-storage.ts` is byte-identical (`getStorageArea`, `getLastRuntimeError`, `read/write/patch/subscribe` shape). ~140 lines of each `*-api.ts` is byte-identical (`readJson`, `extractApiMessage`, `mapErrorResult`, thumbnail ternary, pagination loop). `isRecord` is copied **10 times**. The four `*-api.ts` files are the same file with a noun swapped.

**Fix:** three generic factories collapse ~1,400 lines to ~200:
1. `createStorageModule<T>({ key, area, normalize, fallback })` → `{ read, write, patch, subscribe }`
2. `createYouTubeEndpoint({ url, part, normalizeItem, errorMap, paginate })` → `fetch(accessToken, ...args)`
3. `createStatusCopy<Status>(map)` → `(status, lastError) => Copy | null`

The 4 families become 4 declarative records. This is the single highest-leverage refactor in the codebase and it would have prevented P0-2.

### P1-2. ~600 lines of commented-out AI code rotting in active files

- `src/options.tsx:49-60, 73-86, 167-205, 291-297, 313-314, 337-349, 660-774, 1238` — ~200 lines
- `src/background.ts:6-33, 77-78, 143-171, 209-377` — ~230 lines
- `content-script/src/App.tsx:68-73, 92-98, 105-111, 137-138, 146-149` — ~20 lines
- `content-script/src/watchSoftFocus.ts:5-13, 62-85, 110-193` — ~170 lines

Commented code rots: the surrounding types evolve, the comments don't. The `FocusSettings` type in `src/settings/schema.ts:29-39` still **requires** `personaPreset`, `personaSliders`, `customPersonaInstruction`, `allowMildProfanity` as live fields — so every `normalizeFocusSettings` call and every settings write carries AI fields the UI never sets. The "AI disabled" claim is cosmetic; the data model is still AI-shaped.

**Fix:** branch `phase-3-ai`, delete from `main`, revive by cherry-picking when AI work reopens. Remove the persona fields from `FocusSettings` or make them optional. Branches are cheaper than comments.

### P1-3. Playwright is the wrong runner for ~60% of the test suite

13 of 21 test files never touch a browser `page` — they're pure-function unit tests (`normalizeFocusSettings`, `getPlaylistStatusCopy`, `getFocusOverlayWheelRoute`, `fetchYouTubePlaylists` with a `fetch` mock, etc.) running under Playwright's runner. They `import { expect, test } from "@playwright/test"`, so `npm test` boots the Playwright runner → tries to acquire Chromium → **fails in the sandbox**. `progress.md` complains about this in **8 separate entries** (`:17,22,24,26,28,34,42,48,61`). The sandbox failures are self-inflicted — those tests would run fine under Vitest anywhere.

**Fix:** move the 13 pure-function files to Vitest. Runs in milliseconds, runs anywhere, lets the remaining Playwright suite focus on what only it can do (real DOM/Shadow-DOM behavior). This single change eliminates the dominant failure mode in the progress log.

### P1-4. `options.tsx` (1460 lines) and `content-script/src/App.tsx` (1049 lines) are over the 1k threshold

`OptionsApp` is a single ~1180-line component with 18 `useState`, ~15 handlers, 5 huge inline `Card`s. `App.tsx` mixes 3 unrelated components (`WatchPageFocusFoundation`, `MastheadFocusToggle`, `HomeFocusOverlay`) + ~400 lines of inline `<style>` strings + a hook + icons. Both files are doing 5 jobs.

**Fix:**
- `options.tsx` → `<YouTubeAccountCard>`, `<ImportedPlaylistsCard>`, `<ChannelsCard>`, `<FocusModeCard>`, `<PlaylistShortcutsCard>`. The `ChannelsCard` and `ImportedPlaylistsCard` are already copy-pastes of the same workspace UI — extract `<SelectionWorkspace>`, deletes ~250 lines.
- `App.tsx` → `watch/WatchPageFocusFoundation.tsx`, `masthead/MastheadFocusToggle.tsx`, `home/HomeFocusOverlay.tsx`, `useFocusUiState.ts`. Move the inline CSS to one injected stylesheet or CSS modules — drops the file under 650 lines and stops re-injecting CSS on every render.

### P1-5. `open_options` message breaks the codebase's own convention

`src/background.ts:173`:
```ts
if (message && message.action === "open_options") {
```
Every other message module uses `{ type: ... }` with a shared constant and a type guard (`isConnectYouTubeMessage`, `isFetchYouTubePlaylistsMessage`, etc.). `open_options` uses `action`, no constant, no guard, magic string duplicated between `background.ts:173` and `content-script/src/App.tsx:547`. The one place the codebase violates its own convention.

**Fix:** add `OPEN_OPTIONS_MESSAGE` to a `src/messages.ts` (or `src/ui/messages.ts`) with a type guard, use `type` not `action`.

### P1-6. Dead code kept alive by tests

- `nextPageSeen` — plumbed through 5 files (`schema.ts`, `subscriptions-schema.ts`, `api.ts`, `subscriptions-api.ts`, `background.ts`), fetched/normalized/stored/persisted, **never read by any UI**. Grep `*.tsx` for `nextPageSeen`: zero matches.
- `getFocusOverlayCards` (`focusOverlay.ts:184-253`) — ~70 lines runtime-dead, only `tests/focus-overlay-cards.spec.ts` imports it. `App.tsx` uses `getFocusOverlaySections`.
- `getFocusOverlaySources` (`focusOverlay.ts:108`) — only `tests/youtube-home-overlay.spec.ts` imports it.
- `isYouTubeHomeUrl`, `getMastheadPlacementState` — only test imports.
- `ensureAiSettings`, `patchAiStickerCacheState`, `pruneStoredAiStickerCache`, `subscribeToAiSettings` — exported, never imported by active code.

**Fix:** delete the dead exports and the tests that exist only to test them. If you need them back, git remembers.

### P1-7. Three sources of truth for status enums — already drifted

- Schema `as const` array (`YOUTUBE_PLAYLIST_FETCH_STATUSES`, 8 entries)
- API inline failure union (`PlaylistsApiFailure["status"]`, 4 entries, defined inline in each `*-api.ts`)
- Message response union (`FetchYouTubePlaylistsResponse`, 5 entries in `messages.ts`)

Adding a status to one and forgetting the others typechecks fine. P0-2 is the bug this drift produced.

**Fix:** one `as const` array per family, derive the API failure union and the message response union from it with `(typeof STATUSES)[number]`.

### P1-8. Type safety smells that hide bugs

- `as` casts on `unknown` in every normalizer (`normalize.ts:23`, `subscriptions-api.ts:170`, `channel-api.ts:142`, `preview-api.ts:142`) — the cast can lie, the filter catches the lie at runtime. Should be a runtime narrow on `unknown`.
- `includes(value as Union)` in `schema.ts:82-86`, `subscriptions-schema.ts:81-85`, `auth/schema.ts:130-132` — the cast happens **before** the `includes` check, so the type system is told "trust me" and the runtime check is the only real guard.
- `auth/schema.ts:62-63` silently infers `connected` from `accessToken` presence — masks real desync (token revoked remotely but cached locally).
- `getAuthToken` types `error` as `unknown` but only assigns strings (`background.ts:742`).

### P1-9. Background service-worker issues

- Sequential awaits over independent API calls: `syncSelectedPlaylistPreviews` and `syncSelectedChannelPreviews` loop `for (const x of selected) await fetch(...)` — N round-trips serialized. Use `Promise.all` (with a concurrency cap if quota matters).
- Redundant storage reads: the `subscribeToFocusSettings` listener already has the new settings (handler arg in `storage.ts:87`), but `syncSelectedPlaylistPreviews`/`syncSelectedChannelPreviews` ignore it and re-read twice from storage.
- Empty `catch {}` around `chrome.alarms` (`background.ts:711,719,727`) — `alarms` IS in the manifest, so the only remaining throw modes are real bugs. Empty catch hides them.
- 4× copy-pasted unauthorized-recovery block (`background.ts:460-472, 518-530, 568-582, 627-640`). Extract `handleUnauthorizedYouTubeAuth(message)`.
- `onInstalled` fires 6 fire-and-forget writes — if the popup opens before they settle, state is mid-write.

### P1-10. Content-script performance hazards

- Two `MutationObserver`s on `document.documentElement` with `subtree: true` and **no debounce** (`App.tsx:129-133`, `App.tsx:947-951`). Every YouTube mutation runs a full DOM scan (`extractWatchSuggestionMetadata(document)`, `syncHomeFeedVisibility(document, ...)`). YouTube mutates constantly.
- `revealIntent` in the MutationObserver effect's dep array (`App.tsx:101-144`) — every `dispatchRevealIntent` tears down and recreates the observer on the entire document. Use a ref so the observer stays connected for the route's lifetime.

### P1-11. Test infrastructure debt

- `tests/utils/` and `tests/helpers/` do not exist. Zero shared fixtures, zero helpers, zero custom Playwright fixtures. Everything copy-pasted.
- `baseSettings` literal duplicated across `focus-overlay-cards.spec.ts:10-16` and `focus-overlay-sections.spec.ts:11-17`.
- The "stringify function, eval in page" pattern (`new Function(\`return (${fnText})\`)()`) duplicated across 5 files — bypasses type safety, tests functions in a stringified sandbox unlike production (where they run as part of the bundled content script with real imports). 100 lines of `WATCH_MODULE_DEFS` fixture inline in `watch-soft-focus.spec.ts:19-118` to hand-roll the imports the stringified function lost.
- `tsconfig.json:32` `include` does NOT include `tests/` — `tsc -b` (run by `npm run build`) never typechecks tests. Type errors in tests survive `npm run build` green.

### P1-12. Tests testing implementation, not behavior

- `tests/watch-soft-focus.spec.ts:488-494` — reads `content-script/src/App.tsx` source text and asserts `not.toContain("handleRevealAll")`, `not.toContain(">All<")`, `not.toContain("Show suggestions and comments")`. This is `grep` in a trench coat. Rename the function → test passes while behavior regresses. Delete or replace with a render test.
- `tests/watch-soft-focus.spec.ts:496-498` — empty `test.skip` body with a comment. A TODO pretending to be a test. Delete it.
- `tests/ai-stickers.spec.ts:192-205` — tests that `{ ...original }` spread works. Tests the JS language.
- Copy-text coupling: `expect(cards[0]).toEqual({ subtitle: "Opens on YouTube" })` — a copy edit breaks the test with zero behavior change. Same across `focus-overlay-sections.spec.ts` and all of `youtube-status-copy.spec.ts`.
- `tests/preflight-isolation.spec.ts:27-53` — asserts the *bug* reproduces (injects global CSS, checks h1 margin collapses). Regression test for a problem already fixed by the Shadow DOM mount. Delete or merge as a before/after pair.

### P1-13. Two whole AI test files kept as `describe.skip` — worst of both worlds

`tests/ai-settings.spec.ts:11` and `tests/ai-stickers.spec.ts:26` wrap the entire files (33 tests) in `describe.skip`. They never run, never fail, but show up in `--list` and imply coverage. They still import `@ai-sdk/openai`-backed modules, keeping the AI dependency graph green.

**Fix:** delete and rely on git history, or move to `tests/ai/` with a Playwright `testIgnore` glob.

### P1-14. `chrome.storage.sync` quota not guarded

Settings live under one sync key `youtubeFocusSettings` (`src/settings/schema.ts:11`). `chrome.storage.sync` per-key quota is 8,192 bytes. With up to 12 manual + 12 imported playlists + 5 channels + persona fields + `customPersonaInstruction` (280 chars) + URLs, the key can approach the limit. `writeFocusSettings` checks `lastError` and rejects, but no UI surfaces the failure — the user just sees settings not persisting. No quota guard, no size estimate, no warning.

### P1-15. `lastError` handling inconsistent between read and write

Every storage writer checks `chrome.runtime.lastError`. No reader does (`storage.ts:18-27` and 7 copies):
```ts
area.get(SETTINGS_STORAGE_KEY, (items) => {
  resolve(normalizeFocusSettings(items[SETTINGS_STORAGE_KEY], DEFAULT_FOCUS_SETTINGS));
});
```
Reads can set `lastError` too (quota, serialization). The reader silently resolves with defaults.

## What's actually good

To be fair, this is not all bad:

- **Shadow DOM isolation** (`content-script/src/main.tsx`) is done right — `tests/preflight-isolation.spec.ts` proves Tailwind Preflight doesn't leak into YouTube.
- **The pure-function extraction pattern** (DOM helpers, normalizers, status-copy, reducers) is good discipline — most logic is testable in isolation. The problem is that the tests then don't cover the composition layer.
- **The `normalizeX` defensive pattern** is right for extension storage (you can't trust what's there) — it's just missing versioning (P0-4) and over-applied to non-nullable types (P1-8).
- **The build works**, the lint passes, the AI runtime is genuinely wired off (verified: no active imports of `src/ai/*` from any entry point).
- **The task/progress/architecture documentation is thorough** — most vibe-coded repos have none. This one has too much prose in places (see P1-2), but the discipline is real.
- **The manifest is minimal** (`storage` + `alarms` only) — good permission hygiene for the non-AI release. (The `identity` omission is a feature-flag problem, not permission bloat.)

## Recommended fix order

If you ship nothing else before the Chrome Web Store release, fix these in order:

1. **P0-6** — rename `package.json`. 1 line.
2. **P0-3** — move AI deps out of `dependencies`. 2 lines.
3. **P0-1** — decide whether OAuth ships in the release build. If not, gate the "Connect YouTube" UI behind the same `GOOGLE_CLIENT_ID` build flag. If yes, add `identity` + `oauth2` to the release manifest.
4. **P0-2** — one shared `mapYouTubeApiError`. Fixes a real user-facing bug.
5. **P0-5** — diff before re-fetching in the background settings subscription. Stops burning quota.
6. **P0-4** — add `version: 1` to each stored shape + a migrate hook. Cheap now, impossible after shipping.
7. **P1-2** — branch `phase-3-ai`, delete commented AI code from `main`, remove persona fields from `FocusSettings` or make them optional.
8. **P1-3** — move pure-function tests to Vitest. Eliminates the dominant failure mode in the progress log.

Everything else is debt to pay down during normal work, not a release gate.

## How this audit was run

Three parallel review agents (general subagents) using the `code-review-excellence` and `thermo-nuclear-code-quality-review` skills:
1. Agent 1: deep review of the 3 largest files (`options.tsx`, `content-script/src/App.tsx`, `background.ts`).
